0. 文档怎么用，以及先做哪些决策
这份规划刻意写长。原因是：用 Grok 写文章的内容站，失败模式通常不是「不会写」，而是产品定义含糊——把生成模型当成前台人格、把知识文当资讯农场、把付费墙当成整页弹窗、把用户定义成所有人。下面四条是开工前必须锁死的决策，后面所有章节都建立在它们上面。
	•	产品不是「Grok 写的博客」，而是「可进阶的 AI 知识操作系统 + 科技情报站」。知识库是长期资产，新闻是流量与日活钩子，Grok 是编辑部引擎。
	•	用户不是所有人。免费层服务好奇者，付费转化打「用 AI 干活的职场人」，高客单打工程师和小团队负责人。不做学术顶会媒体、荐股、医疗处方。
	•	内容生产必须人机共创。常识文可半自动，搭建/应用必须可复现，新闻必须人工选题+事实核验，原理文必须引用论文或官方文档。全自动日更长文等于把站点做成内容农场，SEO 和信任会一起死。
	•	付费墙卖的不是「多几篇文章」，而是路径解锁、判断力、可执行资产、持续更新（过时清单）。社群是留存插件，不是主货。
给创始人的读法
第 1–4 章：先对齐定位、用户、竞品空位、内容 DAG。这四章不定，后面做的功能都会漂。
第 5–8 章：商业闸门、站点地图、功能、权限。这是产品经理和设计师的施工图。
第 9–11 章：Grok 流水线、技术架构、仓库与数据表。这是工程开工包。
第 12–15 章：增长、合规、编制、路线图。这是运营和排期。
1. 项目总览
1.1 要解决的真实问题
中文互联网并不缺 AI 文章。缺的是三件事同时成立：
	•	可走完的路：从「听说过 ChatGPT」到「能上线一个文档问答 / 能判断要不要上 Agent」中间有断层。用户原话里的「常识→搭建→应用→原理」中间至少缺选型、工作流、评测运维、失败案例四环。
	•	可相信的更新：模型、工具、价格每周都在变。极客时间式死课程会过时，微信收藏夹式碎片又形不成体系。需要「活教材」：节点带 Last-verified 日期，过时了会被扫描、回写、降级或作废。
	•	可执行的产出：自己打开 ChatGPT / Grok / Claude 也能问。用户愿意付钱，是因为本站给出路径坐标、版本、交叉验证、对照实验、模板仓库，以及「这篇和上周那篇怎么连」。

3.2 关键使用场景（写成任务，不要写成身份）
	•	周一早上 15 分钟：扫完整早报，标出本周是否要改技术选型。
	•	接到「给客服做个知识库」：从岗位测评进入「文档问答」路径，按单元做完，导出上线清单。
	•	模型发布日：看快讯 3 点结论 → 打开对照台看同一任务的成本与质量 → 决定要不要迁。
	•	自己写的提示词失效：到资产库拿本月更新包，同时看到「过时清单」里旧教程被划掉。
	•	带 3 个同事一起学：团队席位共享路径进度，不共享登录（V2）。
3.3 明确不做
	•	不做学术顶会全覆盖媒体。顶会论文只做「值不值得读 + 和哪一层有关」。
	•	不做投资荐股、代币喊单、医疗处方、法律意见。
	•	不做无来源爆料、匿名猛料。
	•	不做日更 50 篇知识长文的 SEO 农场。快讯可以高频，知识文宁缺毋滥。
	•	不做大广场社区。评论和勘误可以有，但主产品不是论坛。通往 AGI 之路已经占了免费共创社区的位置。
	•	V1 不做原生 App、不做浏览器插件、不做微信小程序写作后台。分发可用公众号和邮件。

5. 内容体系：补齐「常识→搭建→应用→原理」的断层
5.1 用户原路径为什么不够
「常识 → 搭建 → 应用 → 原理」是正确的大方向，但按这个四段去写课，读者会在四个地方掉下去：常识之后不知道选什么工具；注册完账号之后不知道怎样形成工作流；做出 Demo 之后不知道怎样判断它能不能上线；想学原理时没有阅读论文和发布说明的能力。所以课程树做成 8 层主路径 + 1 条横切，而不是 4 栏栏目。

5.7 还应该补充的品类（用户原清单之外）
在「AI 知识 + 科技新闻」之外，以下品类不是锦上添花，是补齐商业闭环和搜索入口所必需的。没有它们，站点会变成两栏杂志，留不住 B 类用户。
	•	工具与模型对照台：同一任务、同一提示词、同一评测集，跨模型记录质量、延迟、价格。这是用户无法稳定自己完成的脏活。
	•	可下载资产库：提示词包、n8n/Make 工作流、Notion/CSV 对照表、上线检查单、ROI 测算表。订阅如果只有文章，续费率会很难看。
	•	岗位与行业 playbook：把同一条技术路径翻译成产品、运营、开发、教师、律师助理等任务语言。
	•	评测与失败案例库：专门收藏「看起来能跑、实际上不能上线」的案例。这是建立权威最快的方式。
	•	职业与作品集轨道：不是鸡汤，是「你可以把哪个项目放进简历、评审看什么」。
	•	政策、安全与合规速读：只做「对你的产品有什么影响」，不做空泛伦理长文。
	•	实体页：模型、公司、论文、工具各有永久 URL。这是 SEO 和图谱的交汇点。
	•	勘误与变更日志：作为独立栏目存在。公开改错是反农场的品牌动作。

6. 免费 / 付费边界与商业模式
6.1 付费墙哲学
付费墙服务三个目标，排序不能反：第一，让搜索引擎和 AI 引擎能读到足够多的免费层，站点才能活；第二，让未付费读者感到「方法是完整的，细节被收走了」，而不是「被骗进来」；第三，让已付费读者觉得续费有理由。因此采用 Freemium + Teaser + 计量，硬墙只用于资产。禁止整站硬墙。

6.4 会员到底买到什么（用一封确认邮件能写清）
标准会员开通当天应立刻能感到三件事：一，正在读的那篇 L3 正文和代码展开了；二，邮箱里出现完整周报的历史期；三，下载中心有一个「文档问答上线清单」可以带走。如果开通后只是「文章变多了」，转化和续费都会弱。专业会员还要在 24 小时内收到仓库邀请和对照台权限。
7. 信息架构与站点地图
7.1 导航原则
	•	顶栏不超过 7 项：学习、情报、工具、百科、定价、搜索、登录。项目课放在学习下，不单独占顶栏。
	•	登录后顶栏「学习」变成「工作台」，但 URL 体系公开站与会员站分开，便于缓存和 SEO。
	•	所有内容页必须能回答三个问题：这是第几层、和我正在走的路径什么关系、下一篇是什么。
	•	实体（模型/公司/工具/术语）有独立永久 URL，文章是会过时的，实体页是图谱入口。

8. 全站功能规划（页面级，不是模块名）
8.1 首页
	•	主 CTA：「测一测你卡在哪一层」（2 分钟岗位+目标问卷，结果落到一条路径的某一单元）。
	•	次 CTA：订阅免费早报。聊天入口只在页脚或登录后工作台，避免首页变成又一个对话框。
	•	今日简报 5 条（事实层），每条显示挂接的知识层徽章。
	•	「从这里继续」登录态模块：断点续学。
	•	一条路径的缩略进度条，给访客看完整体系，而不是最新文章瀑布。
8.2 文章页强制模块（没有这些不能发布）
	•	层徽章 + 路径坐标：L3 搭建 · 文档问答 · 第 4/12。
	•	预估阅读时长、更新时间、Last-verified、作者。
	•	目录（免费）。
	•	导语（免费）：这篇解决什么问题、不解决什么。
	•	正文，墙锚点可配置在章节级。
	•	结论与「读完你能做什么」（免费）。
	•	来源卡：每条可点击，类型=官方/论文/新闻/本站旧文。
	•	AI 辅助披露：辅助比例、使用模型、是否经过事实核验。
	•	勘误入口与历史变更。
	•	上一课 / 下一课 / 相关新闻 / 相关概念。
	•	收藏、划线、引用复制。
	•	结构化数据：Article 或 NewsArticle、FAQ、Breadcrumb、paywall 相关字段。
	•	可选：音频版、中英术语悬停。
8.3 学习台与测评
测评不是性格测试。问题只围绕目标（我想做知识库 / 我想提效写作 / 我想理解原理）、当前工具、每周可投入时间、岗位。输出是一条推荐路径 + 起始单元 + 「先不要学什么」。学习台每天最多给 3 个任务，防止把站点做成待办压力源。掌握度来自测验和实验提交，不来自阅读时长。
8.4 搜索与推荐
	•	搜索分栏：概念、路径单元、快讯、工具、资产。
	•	语义检索只走已发布已审校语料。
	•	推荐公式优先：和当前文相关 × 用户尚未读 × 前置已完成 × 不过时。
	•	未登录用户的推荐只按层和热度，不做假个性化。
8.5 站内问答 Ask
	•	只回答本站已审内容覆盖的问题。语料外明确说「本站还没有写过，已记入选题缺口」。
	•	每条回答带段落级引用，点击回到原文高亮。
	•	用量条可见。超限引导升级，不中断到一半再弹窗。
	•	用户可把问答沉淀进笔记。高质量问答经编辑回写后可变成概念卡。
	•	禁止 Ask 成为首页主入口，否则产品会退化成套壳聊天。
8.6 会员、支付、账户
	•	注册：邮箱魔法链接为主，支持 Google / Apple；国内镜像再加微信（V2）。
	•	支付：海外主体走 Stripe（卡、Apple Pay）；人民币走微信/支付宝（通过合作支付或国内主体镜像）。两套账对同一 entitlements。
	•	订单、发票、退款、宽限期、付款失败重试、降档、暂停 1 个月挽留。
	•	防共享：同时在线设备上限，不搞过激指纹。下载水印即可。
	•	兑换码、赠月、学生认证、邀请双方加问答额度（先不要直接给现金）。
8.7 增长功能（V1 就要有）
	•	邮件：欢迎序列、路径催学、早报/周报、即将到期、暂停挽留。
	•	RSS + 会员私有 RSS token。
	•	UTM 与付费墙实验：文末墙 vs 滚动 50% 墙。
	•	社交媒体卡片（标题、层徽章、3 点结论）。
	•	公众号同步（中文获客必需，可先手动+RSS）。
	•	sitemap 分类型、llms.txt、JSON-LD、重定向管理。
	•	内部链接建议器（Studio 内根据图谱推荐）。
8.8 明确不做的功能（写进 backlog 禁区）
	•	V1 不做即时通讯、动态信息流、积分商城、直播、短视频信息流。
	•	不做用户可随便发长文的 UGC 主场。投稿走 Studio 邀请制。
	•	不做「AI 一键生成并发布到全网」的矩阵工具。那是另一门生意，且会污染本站品牌。
	•	不做复杂积分体系。邀请只加额度或赠天。

11. Grok 内容生产流水线
11.1 原则
流水线的目标不是提高字数，是提高「可发布率」和「事后可追溯」。每一篇正式内容都是一个对象，带着状态、来源、成本、责任人。Grok 只允许在 Studio 里被调用，不允许编辑在私人聊天里生成后粘贴进来却不留日志——那种内容一旦出错无法追责，也无法复用提示词。
11.2 状态机
idea → assigned → researching → drafting → factcheck → editing → legal（按需）→ scheduled → published → needs_update → archived
任何状态回退都必须写原因。published 不是终态：过期扫描可以把文章打回 needs_update。

11.4 发布强制字段（缺一不可）
title, slug, level(L0–L7), node_ids[], sources[], ai_assist_ratio, model_used, factcheck_status, reviewer_id, publisher_id, published_at, last_verified_at, expires_at, paywall_tier, paywall_anchor, changelog。没有这些，发布按钮不亮。
11.5 Grok 调用规范
	•	系统提示版本化，存在 /admin/prompts，每次生成记录 prompt_hash。
	•	RAG 只检索已发布已审校语料 + 白名单源（官方文档、论文、公告）。禁止检索未审草稿或随机网页。
	•	输出必须是 CMS JSON schema，禁止直接吐整页 HTML。
	•	温度：快讯 0.2，解释文 0.4，评论草稿 0.6。评论草稿不得直接上线。
	•	generation_log：model、tokens、cost、retrieved_doc_ids、latency。
	•	模型路由：快讯与摘要用便宜快模型；路径与深度用旗舰；代码实验用代码模型。成本看板按篇、按人、按类型可看。
11.6 人审红线
	•	医疗、法律意见、投资建议：默认拒写。
	•	未核验数字、排名、「第一 / 唯一 / 最佳」：拦截。
	•	代码块必须在 CI 或容器里跑通，否则标记「未运行」，不得假装可复制即用。
	•	新闻必须 2 个独立源，除非官方一手。
	•	不得把未公开的用户问答原文写进文章。
11.7 文风与反 AI 味
对外文风：具体、可证伪、先给判断再给解释。禁用「在当今快速发展的人工智能时代」「赋能」「打造闭环」这类空话。比喻只允许一个，且必须服务理解。列表不是文章。判断段由编辑重写，是付费墙后真正值钱的部分，也是最不能自动化的部分。
12. 技术架构、数据模型与仓库结构
12.1 架构原则
	•	内容对象优先：文章、快讯、节点、来源、资产都是一等公民，页面只是渲染。
	•	权益优先于套餐：鉴权查 entitlements，不查「是不是 Pro 字符串」。
	•	生成与发布隔离：worker 能写草稿，不能写 published。
	•	搜索与正文同一事实源：向量库只同步已发布已审校内容。
	•	可替换模型：Grok 是默认引擎，不是架构中心。prompt 与 schema 不绑死某一模型名。

12.7 生成成本的数量级
按 2026 年 9 月公开价，旗舰模型大约输入 $2 / 百万 tokens、输出 $6 / 百万 tokens；快讯和摘要应走更便宜的快模型。粗算：一条 400 字快讯含材料压缩，成本可控制在很低的个位数美分；一篇 4000 字深度若多次重生加核验，可能到几十美分到数美元。真正贵的是对照实验和站内问答。所以 Ask 必须限本站语料、限额度，对照台必须放 Plus。早期整体模型账单目标：MVP 月 ¥500–3,000；V1 若问答放量，单独设预算告警，超过日限额自动降级模型，不超支也不默默降低质量却不告知。
13. 增长、SEO 与分发
13.1 SEO 结构
用 topic cluster，不用关键词堆砌。支柱页是 /topics/[cluster] 与 /learn/[track]，卫星页是概念卡、对照页、工具实体页。内链由图谱生成建议，编辑确认。免费层必须可抓取；付费层按规范提供可见的导语、目录、结论，避免「搜索引擎什么都看不到」。
	•	概念卡瞄准定义类查询：什么是 RAG、什么是 MCP、context window 是什么。
	•	对照页瞄准选择类查询：RAG 和 Agent 的区别、本地模型和 API 怎么选。
	•	路径页瞄准任务类查询：如何做内部知识库、如何评测 RAG。
	•	实体页瞄准品牌词：某模型、某工具的中文解释与变更。
	•	勘误页和 disclosure 页建立信任，也是 AI 搜索引用时的安全垫。

14. 合规、风控与信任
14.1 AI 披露与版权
	•	每篇有固定披露模块：是否 AI 辅助、辅助比例、核验人。不把「AI 生成」藏进页脚。
	•	不转载原文。二次表述 + 链接 + 引用块。图片与图表尽量自绘或使用可授权素材。
	•	用户上传到 Ask 或投稿的材料，默认不进入训练日志对外展示。
	•	对外提供 llms.txt，明确哪些允许被模型抓取，哪些付费层不允许。
14.2 幻觉与更正 SOP
发现事实错误：4 小时内在文首加勘误条，同时写入 /errata。若错误出现在付费判断层并导致读者按错误行动（例如过时的定价、错误的 API 路径），主动赠送一个月会员。重复出错的类型回写到提示词禁区和事实清单模板。这不是客服姿态，是品牌。内容农场与严肃教材的分界就在这里。
14.3 法律与主体
	•	先中文内容、海外主体、Stripe，可避开 V1 被 ICP 卡住。若要国内稳定访问与微信支付原生体验，V2 再做备案镜像站，两站共用内容 API。
	•	隐私政策写清：账户数据、阅读进度、生成日志、支付数据各存在哪、保留多久。
	•	不收集非必要敏感信息。学生认证用最轻材料。
	•	高风险领域拒写，比写了再免责更安全。
14.4 产品风控
	•	反内容农场：知识长文有周配额，快讯有双源规则。
	•	反账号共享：设备上限 + 下载水印，不做羞辱式弹窗。
	•	反提示词泄露：系统提示只在后台，生成日志按角色可见。
	•	反超支：模型日预算、Ask 降级策略、异常线程熔断。
	•	反过时：每周扫描「已停更模型 / 已失效价格 / 已变更 API」。

附录 A. 文章页与发布检查单
A1 文章页模块顺序
层徽章与路径坐标 → 标题 → 元信息（作者、时长、发布、Last-verified）→ 一句话「读完能做什么」→ 目录 → 导语 → 正文（含墙锚点）→ 结论 → 练习或下一步 → 来源卡 → AI 披露 → 勘误 → 相关节点与相关新闻 → 升级组件（若未授权）→ 划线与收藏。
A2 发布检查单
	•	学习目标是否用可观察动词写成（能画出 / 能算出 / 能上线），而不是「了解」「掌握」。
	•	是否标明层、前置、下一步。
	•	来源是否可点开，新闻是否双源或官方一手。
	•	事实清单是否全处理。
	•	代码是否运行或已标未运行。
	•	付费墙锚点是否切在「判断/步骤/表格」而不是第一段。
	•	SEO：标题、描述、slug、OG、JSON-LD、内链至少 3 条。
	•	披露、作者、Last-verified、expires_at 已填。
	•	是否需要同步邮件、公众号、RSS。

附录 C. 给 Grok 的写作指令骨架（Studio Brief）
每篇生成前，编辑必须填完下列字段，系统再去调模型。不允许只丢一个标题。
	•	读者：A/B/C 哪一层，岗位，本周任务。
	•	层级：L0–L7，前置节点 ID，完成后解锁的节点。
	•	学习目标：1–3 条可观察结果。
	•	必引源：URL 列表。禁止源：竞品原文、未核实数字。
	•	必须出现的零件：定义 / 反例 / 对照 / 练习，按需勾选。
	•	付费墙切在哪一节。
	•	禁止项：口号、无来源排名、医疗法律投资建议、假装代码已运行。
	•	输出 schema：title, excerpt, outline, sections[], claims[], source_spans[], next_node, quiz[]。

结束时记住的一句话
阶见要赢的不是「Grok 写得比别人快」，而是「读者永远知道自己在第几层、下一件该做什么、以及哪篇文章已经过时」。
把这句话写进首页、写进编辑部墙、写进发布检查单。功能可以砍，这条不能砍。
